# MCP owner contributor entry

Read [local vision](docs/VISION.md), [owner contract v1](contracts/mcp-owner.v1.md)
and [README](README.md) before changing behavior. They apply the approved family
direction and reference upstream/owner authority; they do not ratify new scope.

Change only this repository in an owned checkout/state root. Preserve native
history, original artifacts, identities and unknown receipts. Never replay work
or infer safe remote retirement from disconnect. No real external-effect tools,
real provider consent, package publication, merge or deployment without applicable
user authorization. Keep existing host/client/native/resources ownership intact.

For a shared semantic change, identify the inherited clause, producer/consumers,
falsifier and acceptance boundary and coordinate with the authority owner. Keep
exact executable schemas as the field authority. Review every known affected
Amplifier module implementation before a module-class change; this optional
broker does not replace the native module or Core/Foundation runtime.

Run checks appropriate to changed behavior; documentation-only changes require
link/source/manifest validation, not unnecessary runtime reruns. Record source,
installed package, fixtures, actual accounts/browser and adoption separately.
Do not rewrite sealed evidence or claim a documentation successor reran it.

This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it.

## Ecosystem maps

Keep this repository's README and product-page maps aligned with the
[Constellation map guide](https://github.com/microsoft/amplifier-constellation/blob/main/docs/ecosystem-maps.md)
and its canonical registry; start with this repository's
`docs/ecosystem-map.json`. When creating, renaming, splitting, retiring, or
changing a role, interface, parent, or dependency, inspect incoming and outgoing
relationships and update every affected parent/consumer map and link, including
the centralized product pages. Regenerate from source data and synchronize local
records/images rather than hand-editing generated images. Describe actual
boundaries and optional choices; a role highlight is not a compatibility claim.
Documentation work does not authorize deployment or resume paused product work.
